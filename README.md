# Тестовое задание: Постобработка OCR паспорта РФ

## 1. Описание решения
Разработан алгоритм постобработки результатов OCR-модели для паспортов РФ на языке Python (без использования сторонних ML-библиотек, работает на CPU). 
Основной приоритет — минимизация False Accept (принятие документа с ошибкой), так как это критично для бизнеса.

## 2. Логика работы (Каскад проверок)
Для каждого документа выполняется ряд фильтров:
1. **Проверка качества снимка:** Отклоняются документы с бликом `glare > 0.2` и низкой резкостью `sharpness < 90`.
2. **Проверка уверенности:** Отклоняются поля с `conf < 0.96` и символы с `char_conf < 0.95`.
3. **Валидация форматов:** 
   - Даты проверяются на формат `ДД.ММ.ГГГГ` и реалистичность (год от 1950 до 2026, дата рождения не позже 2012).
   - Код подразделения сверяется со справочником `subdivisions.csv`.
   - Номер лицензии строго по маске `XX XX XXXXXX`.
4. **Семантические проверки:** 
   - Запрет латиницы и цифр в ФИО.
   - Наличие ключевых слов в полях «Кем выдан» (ОВД, МВД) и «Место рождения» (ОБЛ, РАЙОН).
5. **Сверка с MRZ:** Реализована функция транслитерации латиницы из машиночитаемой зоны (MRZ) обратно в кириллицу для сверки с визуальной зоной (`viz`). При расхождении документ отклоняется.

* **Принято документов:** 645
* **Отклонено документов:** 1355

## 4. Прогноз ошибок
Опираясь на результаты тестирования на `train_predictions.jsonl` (где точность среди принятых составила 94.4% при 50 ошибках), я прогнозирую:
* **Количество ошибочно принятых документов на тесте:** ~30–35 штук (около 1.5% от всей тестовой выборки).
* **Обоснование:** Тестовая выборка имеет схожее распределение по качеству. Мы намеренно отклонили много документов, чтобы обеспечить высокую надежность. Алгоритм работает по принципу «лучше отклонить хороший документ, чем принять плохой».
